# RuRBW Service Restorer

Включает обратно системные службы Windows, которые сносят твикеры. Один клик, без ковыряния в `services.msc`.

## Зачем

На ScreenShare никто не ищет папку с читом. Проверяющий поднимает историю запуска программ — что и когда стартовало на компе. Эту историю ведут обычные службы винды: журнал событий, PcaSvc, SysMain, драйвер BAM и ещё несколько.

Твикеры их вырубают. Дальше по цепочке: истории нет, проверяющий не может закрыть проверку, ты получаешь бан за Disabled Services. Читов при этом не было, и ты обычно даже не в курсе, что что-то нарушил.

Утилита возвращает эти службы в заводское состояние. Только включает — ничего не выключает и не удаляет.

## Запуск

`Win+R` → `cmd` → Enter. Вставить одну строку:

```
powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/slurov/rurbw-service-restorer/v1.0.2/fix.ps1 | iex"
```

Винда попросит права администратора — жми «Да». Без них службы не изменить, это ограничение самой Windows, а не утилиты.

Дальше в окне жмёшь «Включить выбранные службы» и соглашаешься на перезагрузку. Часть изменений применяется только после неё.

Ставить ничего не надо. PowerShell уже есть в любой Windows 10 и 11.

## Что трогает

| Служба | Имя в системе | Зачем проверяющему |
|---|---|---|
| SysMain | `SysMain` | учёт запускавшихся программ |
| Помощник совместимости | `PcaSvc` | пишет, какие программы запускались |
| Политика диагностики | `DPS` | без неё не работают другие журналы |
| Журнал событий | `EventLog` | главный источник истории системы |
| Планировщик заданий | `Schedule` | задачи по расписанию |
| Поиск Windows | `WSearch` | индекс файлов на диске |
| Сведения о приложении | `Appinfo` | запуск программ от админа |
| Обнаружение SSDP | `SSDPSRV` | устройства в локальной сети |
| Подключённые устройства | `CDPSvc` | связанные устройства |
| Телеметрия | `DiagTrack` | диагностика Windows |
| Узел службы диагностики | `WdiServiceHost` | диагностика |
| Узел системы диагностики | `WdiSystemHost` | диагностика |
| Активность приложений | `bam` (драйвер) | время запуска программ |
| Активность рабочего стола | `dam` (драйвер) | активность в спящем режиме |

`DcomLaunch` и `PlugPlay` утилита показывает, но не меняет — правкой их типа запуска можно убить загрузку винды. Галочка на них недоступна, если твикер добрался и до них — утилита подскажет, что делать руками.

Три вещи про эту таблицу:

**Ставится заводское значение, а не «побольше».** У `Appinfo`, `SSDPSRV` и обоих `Wdi*` заводской тип запуска — «Вручную», его утилита и ставит. Если у тебя уже стоит сильнее заводского — не трогает.

**`bam` и `dam` — не службы, а драйверы ядра** (`bam.sys`, `dam.sys`). Поэтому другие утилиты показывают у них «Unknown»: `Get-Service` с драйверами работает криво. Тут состояние читается прямо из реестра.

**Если службы нет в системе** (бывает на облегчённых сборках) — напишет «Не найдена» и пойдёт дальше.

## Почему это безопасно

Скрипт — один файл `fix.ps1`, на русском и с комментариями. Открой и посмотри, это быстро.

Во всём файле семь команд, которые вообще что-то меняют. Найди поиском, убедись, что других нет:

- `Set-Service -StartupType`, `sc.exe config`, `Set-ItemProperty` — включают службу
- `Start-Service` — запускает её
- `Set-Content` — пишет отчёт на рабочий стол, только по кнопке
- `shutdown /r` и `shutdown /a` — перезагрузка и отмена, обе по кнопке

Первые четыре лежат внутри `Repair-Service`, и перед ними стоит проверка: тип запуска должен быть одним из четырёх «включающих», имя службы — из таблицы в начале файла. Значения «отключить» нет ни в таблице, ни в функциях перевода типа запуска. Отключить службу нечем чисто физически, даже если бы я накосячил в коде. `Stop-Service`, `Remove-Item`, `reg delete`, `taskkill` в файле не встречаются.

Наружу не уходит ничего. Единственное обращение в сеть — повторная загрузка этого же скрипта, когда он перезапускает себя от админа.

В системе не остаётся: ни служб, ни задач в планировщике, ни автозагрузки. Закрыл окно — осталось только то, что ты включил, и отчёт, если сохранял.

Три длинные base64-строки в начале файла (`$IMG_LOGO36`, `$IMG_LOGO16`, `$IMG_DISCORD`) — это картинки, логотип и значок Discord. Они уходят только в `Image.FromStream` и выполниться не могут. Проверить можно так:

```powershell
$code = Get-Content .\fix.ps1 -Raw -Encoding UTF8
$b64 = [regex]::Match($code, "IMG_LOGO36\s*=\s*'([^']+)'").Groups[1].Value
[IO.File]::WriteAllBytes("$env:TEMP\rurbw-logo.png", [Convert]::FromBase64String($b64))
```

Чтобы не выглядело замалчиванием:

- Ты запускаешь код из интернета с правами админа. Это всегда вопрос доверия к ссылке — читай следующий раздел.
- `DiagTrack` и `CDPSvc` — телеметрия Microsoft. Отключал их осознанно ради приватности — сними галочки, утилита трогает только выбранное. Но журналы, которые они ведут, проверяющему нужны.
- Кнопка «Перезагрузить» правда перезагружает, через 10 секунд. Отмена — кнопкой в окне отсчёта или `shutdown /a`.
- В отчёте есть имя компа и учётки, чтобы проверяющий видел, что отчёт твой. Файл остаётся у тебя, никуда не уходит, но публично выкладывать его не надо.

Разбор того, что скрипт может и чего не может сделать с системой — в [docs/security-review.md](docs/security-review.md).

## Запускай только официальную ссылку

Команда выполняет код с внешнего адреса с правами админа. Подменят ссылку — выполнят что угодно.

Официальная команда есть только на rurbw.pro и в Discord — discord.gg/rurbw. Любой другой вариант скам, даже если выглядит один в один. В адресе должно быть ровно `raw.githubusercontent.com/slurov/rurbw-service-restorer/` и номер версии.

«Улучшенная версия», «то же самое, но .exe», архив с паролем, файл в лс — тоже скам. Эта утилита не просит качать .exe и не просит отключать антивирус.

Если умеешь считать SHA256 — вот сумма `fix.ps1` версии v1.0.2, она же продублирована на rurbw.pro:

```
C5981157C901780A40F59A0D9795EAEF7542D0A18353636CC0CA7B3A203581BE
```

## Почему в ссылке версия, а не main

Ветка `main` меняется с каждым коммитом. Если бы команда смотрела туда, один и тот же текст в чате выполнял бы разный код в разные дни, и никто бы не заметил.

Тег указывает на конкретную версию файла. Защита тегов в репозитории включена, так что подменить код под уже выпущенной версией задним числом нельзя. Новые версии выходят под новыми тегами.

## Если не работает

**«Выполнение сценариев отключено в этой системе»** — команду вставили не целиком. В ней есть `-ExecutionPolicy Bypass`, который это снимает.

**Нажал «Нет» в UAC** — утилита покажет окно с кнопкой перезапуска, жми её и подтверждай.

**Скачал файл и запустил двойным кликом — ошибки или иероглифы** — так запускать не надо. PowerShell 5.1 при запуске через `-File` читает файл в кодировке системы, и на русской винде он ломается. Файл специально сохранён без BOM, иначе не работает `irm | iex`, которым пользуются все остальные. Запускай командой из раздела «Запуск».

**«Не удалось включить службу»** — обычно политика Windows или сторонняя программа держит службу. Текст ошибки будет в отчёте.
