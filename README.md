# RuRBW Service Restorer

Утилита для Russian Ranked Bedwars. Включает обратно системные службы Windows,
которые вырубают «твикеры для оптимизации», — в один клик, без ковыряния
в `services.msc`.

## Зачем это нужно

На ScreenShare проверяющий не ищет файлы читов. Он поднимает историю запуска
программ: что и когда стартовало на компьютере. Эту историю ведут обычные
службы Windows — журнал событий, помощник по совместимости, SysMain,
драйвер BAM и ещё несколько.

«Оптимизаторы FPS» их отключают. Дальше происходит следующее: проверяющий
не может доказать, что чит не запускался, отсутствие истории засчитывается
как попытка её замести, игрок получает бан за Disabled Services. При этом
он ничего не читерил и обычно вообще не понимает, что нарушил.

Утилита возвращает эти службы в заводское состояние. Она только включает —
ничего не выключает и не удаляет.

## Запуск

Win+R, набрать `cmd`, Enter. Дальше вставить одну строку:

```
powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/slurov/rurbw-service-restorer/v1.0.1/fix.ps1 | iex"
```

Windows спросит права администратора — нужно нажать «Да», без них служб
не изменить, это ограничение самой Windows. Дальше в окне нажать
«Включить выбранные службы» и согласиться на перезагрузку: часть изменений
применяется только после неё.

Ставить ничего не надо, PowerShell уже есть в любой Windows 10 и 11.

## Какие службы трогает и почему

| Служба | Имя в системе | Зачем проверяющему |
|---|---|---|
| SysMain | `SysMain` | ведёт учёт запускавшихся программ |
| Помощник по совместимости | `PcaSvc` | пишет, какие программы запускались |
| Служба политики диагностики | `DPS` | без неё не работают другие журналы |
| Журнал событий Windows | `EventLog` | главный источник истории системы |
| Планировщик заданий | `Schedule` | задачи по расписанию |
| Поиск Windows | `WSearch` | индекс файлов на диске |
| Сведения о приложении | `Appinfo` | запуск программ от администратора |
| Обнаружение SSDP | `SSDPSRV` | устройства в локальной сети |
| Платформа подключённых устройств | `CDPSvc` | связанные устройства |
| Телеметрия и диагностика | `DiagTrack` | диагностика Windows |
| Узел службы диагностики | `WdiServiceHost` | диагностика |
| Узел системы диагностики | `WdiSystemHost` | диагностика |
| Активность приложений | `bam` (драйвер) | пишет время запуска программ |
| Активность рабочего стола | `dam` (драйвер) | активность в спящем режиме |

Две службы утилита показывает, но не меняет: `DcomLaunch` и `PlugPlay`.
Правка их типа запуска может сломать загрузку Windows, поэтому галочка
на них недоступна. Если твикер добрался и до них — утилита подскажет,
как включить их вручную.

Несколько вещей, которые стоит знать про эту таблицу:

**Возвращается заводское значение, а не «побольше».** У `Appinfo`, `SSDPSRV`
и обоих `Wdi*` заводской тип запуска — «Вручную», и утилита ставит именно его,
а не «Автоматически». Если тип запуска у тебя уже сильнее заводского,
она его не тронет.

**`bam` и `dam` — не службы, а драйверы ядра** (`bam.sys`, `dam.sys`).
Поэтому другие утилиты показывают у них состояние «Unknown»: `Get-Service`
с драйверами работает криво. Здесь состояние читается прямо из реестра.

**Если службы нет в системе** — такое бывает на «облегчённых» сборках Windows —
утилита напишет «Не найдена» и пойдёт дальше.

## Почему это безопасно

Скрипт лежит одним файлом, [`fix.ps1`](fix.ps1), на русском и с комментариями.
Не хочешь верить на слово — открой и проверь, это реально быстро.

Во всём файле ровно семь команд, которые вообще что-то меняют. Найди их поиском,
и убедись, что других нет:

- `Set-Service -StartupType`, `sc.exe config`, `Set-ItemProperty` — включают службу
- `Start-Service` — запускает её
- `Set-Content` — пишет отчёт на рабочий стол, только если нажать кнопку
- `shutdown /r` и `shutdown /a` — перезагрузка и её отмена, обе по кнопке

Первые четыре живут только внутри функции `Repair-Service`, и перед ними стоит
проверка: тип запуска обязан быть одним из четырёх «включающих», а имя службы —
из таблицы в начале файла. Значения «отключить» нет ни в этой таблице,
ни в функциях, которые переводят тип запуска для записи. То есть отключить
службу нечем — даже если бы я где-то ошибся в коде. Слов `Stop-Service`,
`Remove-Item`, `reg delete`, `taskkill` в файле нет вообще.

Наружу не уходит ничего. Единственное обращение в сеть во всём файле — повторная
загрузка этого же самого скрипта, когда он перезапускает себя от администратора.
Ни телеметрии, ни логов, ни имени компьютера.

В системе утилита не остаётся: не создаёт служб, задач в планировщике и записей
в автозагрузке. Закрыл окно — осталось только то, что ты сам включил, и отчёт,
если сохранял. И там нет ни одной строки, которая расшифровывается или
компилируется на ходу, и ни одного обращения к системным библиотекам напрямую —
это просто текст, делающий то, что в нём написано.

Отдельно, чтобы не выглядело замалчиванием:

- **Ты запускаешь код из интернета с правами администратора.** Это всегда вопрос
  доверия к ссылке — смотри следующий раздел.
- **`DiagTrack` и `CDPSvc` — это телеметрия Microsoft.** Если ты отключал их
  осознанно ради приватности, сними с них галочки: утилита трогает только
  выбранное. Но проверяющему нужны журналы, которые они ведут.
- **Кнопка «Перезагрузить» правда перезагружает** через 10 секунд. Отменить
  можно кнопкой в окне отсчёта или командой `shutdown /a`.
- **В отчёте есть имя компьютера и учётной записи.** Так проверяющий поймёт,
  что отчёт твой, а не скинутый в чат чужой. Файл остаётся у тебя, никуда
  не отправляется, но выкладывать его публично не стоит.

## Запускай только официальную ссылку

Команда выполняет код с внешнего адреса с правами администратора. Подменив
ссылку, тебе выполнят что угодно.

**Официальная команда публикуется только на ресурсах rurbw.pro** — на сайте
и на Discord-сервере **discord.gg/rurbw**. Любой другой вариант команды —
скам, даже если он выглядит похоже. В адресе должно быть ровно
`raw.githubusercontent.com/slurov/rurbw-service-restorer/` и дальше номер
версии, например `v1.0.1`.

«Улучшенная версия», «то же самое, но .exe», архив с паролем, файл из личных
сообщений — тоже скам. Эта утилита никогда не просит скачать `.exe` и никогда
не просит отключить антивирус.

### Почему в ссылке номер версии, а не `main`

Команда качает файл по тегу `v1.0.1`, а не из ветки `main`. Разница важная.

Ветка `main` меняется с каждым коммитом: что лежит в ней сегодня, завтра может
быть другим. Если бы команда смотрела в `main`, то один и тот же текст команды
в чате выполнял бы разный код в разные дни — и никто бы этого не заметил.

Тег указывает на одну конкретную версию файла. В репозитории включена защита
тегов, поэтому подменить код под уже выпущенной версией задним числом нельзя:
команда с `v1.0.1` всегда выполняет ровно тот файл, который вышел как `v1.0.1`.
Новые версии выходят под новыми тегами.

## Как проверить самому

Собирать нечего, это один файл без зависимостей. Проверить можно так.

### Контрольная сумма

SHA256 файла `fix.ps1` версии `v1.0.1`:

```
8F39D56FE1D28099B8E26807C8DA3F7BDBB0FB4A2C8D0020B76B60A1927BCEC1
```

Проверить можно из того же окна cmd, одной строкой. Файл скачается
во временную папку, в конце выведется его хеш:

```
powershell -NoProfile -Command "Invoke-WebRequest https://raw.githubusercontent.com/slurov/rurbw-service-restorer/v1.0.1/fix.ps1 -OutFile $env:TEMP\rurbw-fix.ps1 -UseBasicParsing; (Get-FileHash $env:TEMP\rurbw-fix.ps1 -Algorithm SHA256).Hash"
```

Хеш должен совпасть символ в символ. Та же сумма публикуется рядом с командой
на rurbw.pro — сверяй с ней: если кто-то подменит файл, ему придётся подменить
и сумму в двух независимых местах.

Если хочешь запустить **именно проверенный файл** — открой cmd от имени
администратора и выполни:

```
powershell -NoProfile -ExecutionPolicy Bypass -Command "iex (Get-Content $env:TEMP\rurbw-fix.ps1 -Raw -Encoding UTF8)"
```

Тогда утилите не нужно повышать права, и повторной загрузки не будет —
выполнится ровно тот файл, хеш которого ты только что проверил. Если запустить
из обычного окна, утилита при запросе прав скачает себя заново по той же ссылке.

Не запускай файл через `-File` или «Выполнить с помощью PowerShell»: Windows
PowerShell 5.1 прочитает его в кодировке системы, и на русской Windows скрипт
не запустится. Файл специально сохранён без BOM — с ним ломается запуск через
`irm | iex`, которым пользуются все остальные.

### Код и синтаксис

Сверить, что по ссылке из команды лежит ровно то же, что в репозитории —
открой raw-ссылку в браузере и сравни с [`fix.ps1`](fix.ps1). Подробный разбор
того, что скрипт может и чего не может сделать с системой, —
в [docs/security-review.md](docs/security-review.md).

Проверить синтаксис, ничего не запуская (это уже в окне PowerShell, не cmd):

```powershell
$code = Get-Content .\fix.ps1 -Raw -Encoding UTF8
$errors = $null
[System.Management.Automation.PSParser]::Tokenize($code, [ref]$errors) | Out-Null
$errors
```

Посмотреть, что было со службой до и после:

```powershell
sc qc SysMain
sc qc bam
```

И сохранить отчёт кнопкой в окне — там состояние всех служб до и после,
это же можно показать проверяющему.

## Если что-то пошло не так

**«Выполнение сценариев отключено в этой системе»** — команду вставили не целиком,
в ней есть `-ExecutionPolicy Bypass`, который это снимает.

**Нажал «Нет» в окне UAC** — утилита покажет окно с кнопкой перезапуска,
нажми её и подтверди запрос.

**После перезагрузки служба снова отключена** — значит твикер сидит
в автозагрузке и выключает её при каждом старте. Сначала удали твикер,
потом запускай утилиту.

**«Не удалось включить службу»** — обычно это политика Windows или сторонняя
программа, которая держит службу. Текст ошибки будет в отчёте.
