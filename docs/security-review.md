# Что скрипт может и чего не может

Утилита запускается с правами администратора одной командой из интернета,
поэтому вопрос «а что она вообще делает» законный. Здесь разбор для тех,
кто хочет проверить сам, а не верить на слово.

## Всё, что скрипт способен изменить

Семь команд, больше в файле нет ничего изменяющего:

| Команда | Где | Что делает |
|---|---|---|
| `Set-Service -StartupType` | `Repair-Service` | ставит службе заводской тип запуска |
| `sc.exe config <имя> start=` | `Repair-Service` | то же для драйверов и отложенного автозапуска, которые `Set-Service` в PowerShell 5.1 не умеет |
| `Set-ItemProperty ... 'Start'` | `Repair-Service` | запасной путь для `bam` и `dam`, если `sc.exe` недоступен |
| `Start-Service` | `Repair-Service` | запускает службу |
| `Set-Content` | `Export-Report` | пишет отчёт на рабочий стол, только по кнопке |
| `shutdown.exe /r /t 10` | `Invoke-Reboot` | перезагрузка, только по кнопке |
| `shutdown.exe /a` | окно отсчёта | отмена той же перезагрузки, по кнопке |

Проверить можно поиском по файлу. Заодно убедиться, что в нём нет
`Stop-Service`, `Restart-Service`, `Remove-Service`, `Remove-Item`,
`New-Item`, `Move-Item`, `New-Service`, `sc.exe create`, `schtasks`,
`Register-ScheduledTask`, `netsh`, `bcdedit`, `takeown`, `icacls`,
`Set-ExecutionPolicy`, `Add-MpPreference` — ничего этого там нет.

## Почему отключить службу нечем

Первые четыре команды находятся только внутри `Repair-Service`, и перед
ними стоит проверка:

```powershell
if ($State.Target -notin @('Automatic', 'AutomaticDelayed', 'Manual', 'System')) { ... отказ ... }
if ($State.Name -notmatch '^[A-Za-z0-9_]{1,64}$') { ... отказ ... }
```

Вдобавок значения «отключить» нет ни в таблице `$SERVICES`, ни в функциях
`ConvertTo-ScStartValue` и `ConvertFrom-StartupName`, которые переводят тип
запуска для записи. Читать `Disabled` утилита умеет, записывать — нет.

## Подстановка значений

Имена служб берутся только из таблицы `$SERVICES` в начале файла. Ни ввода
от пользователя, ни данных из сети в этот путь не попадает, плюс имя
дополнительно проверяется регуляркой выше — пробел, кавычка, `&` или `;`
через неё не пройдут, поэтому подставить постороннюю команду в вызов
`sc.exe` нельзя.

Путь к реестру собирается из того же проверенного имени, обращение идёт
через `-LiteralPath`. Имя файла отчёта складывается из даты, пользовательских
данных в нём нет. Аргументы `shutdown` — литералы.

## Сеть

Одно обращение на весь файл: `Invoke-RestMethod` внутри команды, которую
получает копия, запущенная от администратора. Это GET за самим скриптом —
файла на диске нет, потому что запуск идёт через `irm | iex`, и другого
способа передать себя в новый процесс не существует.

Наружу не уходит ничего: ни имени компьютера, ни имени пользователя, ни
состояния служб. Ни одного POST, ни `WebClient`, ни сокетов в файле нет.

Адрес захардкожен константой `$SCRIPT_URL` и указывает на тег релиза, а не
на ветку — чтобы от администратора выполнился ровно тот код, который лежит
в репозитории под этой версией. Теги в репозитории защищены от удаления
и перезаписи, так что подменить код под уже выпущенной версией нельзя.

## Права и следы

Права администратора запрашиваются один раз при старте. Повторный запрос
возможен, только если нажать кнопку перезапуска в окне отказа.

После закрытия от утилиты не остаётся ничего: она не создаёт служб, задач
в планировщике, записей в автозагрузке и файлов, кроме отчёта, если его
сохранить. В файле нет ни одного обращения к системным библиотекам и ни
одной строки, которая компилируется во время работы.

Декодируется в файле ровно одно — три картинки из base64 (`$IMG_LOGO36`,
`$IMG_LOGO16`, `$IMG_DISCORD`): логотип сервера и значок Discord. Они идут
только в `Image.FromStream` и выполниться не могут. Как вытащить их в PNG
и посмотреть — в README, раздел «Почему это безопасно».

## Что будет, если прервать работу

Окно нельзя закрыть, пока идёт включение служб. Но даже если убить процесс
через диспетчер задач, промежуточного состояния не возникнет: каждая операция
независима и только добавляет. Часть служб окажется включена, остальные
останутся как были — повторный запуск доделает остальное. Состояния «служба
сломана на середине» не бывает, потому что обратной операции в утилите нет.

Если перезагрузка уже запланирована другой программой, утилита это увидит
(код 1190) и скажет об этом, а чужую команду отменять не станет.

## Известные ограничения

- Ты запускаешь код из интернета с правами администратора. Это неустранимо:
  без администратора служб не изменить. Защита — открытый исходник и
  зафиксированная ссылка, поэтому важно брать команду только с rurbw.pro
  или из discord.gg/rurbw.
- `DiagTrack` и `CDPSvc` — телеметрия Microsoft. Утилита включает их обратно,
  потому что проверяющему нужны их журналы. Если они отключались осознанно —
  снимите с них галочки, утилита трогает только выбранное.
- Отчёт содержит имя компьютера и учётной записи. Это нужно, чтобы отчёт
  нельзя было выдать за чужой. Файл локальный, никуда не отправляется.
