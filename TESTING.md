# Что прогнать перед релизом

Проверять лучше в Песочнице Windows (есть в Windows 10/11 Pro и Enterprise)
или на виртуалке со снапшотом: половина пунктов требует сначала отключить
службы, а потом чинить. В песочнице сразу права администратора, поэтому
раздел «Повышение прав» проверяется уже на обычном ПК по боевой ссылке.

## Перед первым запуском

- [ ] В `$SCRIPT_URL` стоит настоящий адрес репозитория с тегом релиза,
      а не `main`. В настройках репозитория включена защита тегов `v*`.
- [ ] Тот же адрес в README — в команде запуска, в разделе про скам
      и в команде проверки хеша.
- [ ] SHA256 в README совпадает с `Get-FileHash .\fix.ps1 -Algorithm SHA256`.
      Любая правка `fix.ps1` меняет хеш — пересчитать перед тегом.
- [ ] В `fix.ps1` **нет** BOM: первые байты `3C 23` («<#»), а не `EF BB BF`.
      С BOM запуск через `irm | iex` падает с «Missing argument in parameter list».
- [ ] **Главная проверка перед каждым тегом** — разобрать файл ровно в том виде,
      в каком его получает `iex`. Проверка ничего не запускает. В PowerShell:
      ```powershell
      $s = Invoke-RestMethod https://raw.githubusercontent.com/slurov/rurbw-service-restorer/main/fix.ps1
      $e = $null
      [System.Management.Automation.Language.Parser]::ParseInput($s, [ref]$null, [ref]$e) | Out-Null
      $e.Count   # должно быть 0
      ```
      Проверка файла с диска (`ParseFile`, `Get-Content`) эту ошибку не ловит:
      при чтении с диска PowerShell сам отбрасывает BOM.

## Повышение прав

- [ ] Запуск из обычного cmd — появляется запрос UAC.
- [ ] «Да» — открывается окно, в шапке зелёный бейдж «Администратор»,
      старое окно PowerShell закрылось само.
- [ ] «Нет» — появляется окно «Нужны права администратора» с кнопкой
      перезапуска. Кнопка работает, повторный отказ окрашивает подсказку
      в красный и не роняет окно.
- [ ] Запуск сразу из админского cmd — второго UAC нет.
- [ ] Учётка без прав администратора — UAC просит пароль, отмена ведёт
      в окно отказа, а не в падение.
- [ ] Отключить интернет после запуска команды, но до нажатия «Да» —
      должно появиться окно «Не удалось загрузить утилиту», а не молча
      закрывшаяся консоль.

## Сканирование

- [ ] Чистая система: все строки обычные, сводка зелёная, главная кнопка
      неактивна.
- [ ] Отключить `SysMain` и `DPS` через `services.msc`, нажать «Обновить» —
      строки краснеют, поднимаются наверх, галочки проставлены.
- [ ] Остановить службу с автозапуском, не отключая — строка жёлтая,
      «Остановлена», тип запуска «Автоматически».
- [ ] `DcomLaunch` и `PlugPlay` — галочка недоступна всегда.
- [ ] Отключённый `EventLog` (через реестр, `Start = 4`, затем перезагрузка) —
      строка красная, галочка доступна. После починки `sc qc EventLog`
      показывает `AUTO_START`, после перезагрузки служба работает.
- [ ] Отключённый `PlugPlay` или `DcomLaunch` (только на песочнице!) — строка
      красная, галочка недоступна, в колонке «Что делает» жёлтая подсказка
      про `services.msc`.
- [ ] Службы нет в системе (LTSC без `DiagTrack`) — серая строка,
      «Не найдена», ничего не падает.
- [ ] Windows 10 и Windows 11 отдельно: у `PcaSvc` заводское значение разное,
      и на чистой десятке он не должен подсвечиваться как проблема.
- [ ] `bam` и `dam` показывают «Системный», а не «Неизвестно».
      Сверить с `sc qc bam` и `sc qc dam`.

## Исправление

- [ ] Отключить 5 служб, нажать «Включить выбранные» — карточка сводки
      сменяется прогрессом, счётчик идёт `0/5 … 5/5`, видно имя текущей службы.
- [ ] Окно не белеет и не помечается как «Не отвечает».
- [ ] Во время работы окно не закрывается: «крестик» и Alt+F4 игнорируются,
      в строке состояния «Идёт включение служб — дождитесь окончания».
- [ ] После завершения таблица пересканирована, появился диалог
      «Службы включены».
- [ ] `sc qc` для каждой починенной службы показывает ожидаемый `START_TYPE`.
      У `WSearch`, `PcaSvc` и `CDPSvc` должно быть `AUTO_START (DELAYED)`,
      на Win10 у `PcaSvc` — `DEMAND_START`.
- [ ] Сравнить весь вывод `sc qc` до и после: измениться должна одна строка
      `START_TYPE`, путь к файлу, учётная запись и зависимости — нетронуты.
- [ ] Сломать одну службу так, чтобы починка не прошла (запретить доступ
      к её ключу реестра) — в сводке «Ошибок: 1» с текстом исключения,
      остальные починились.
- [ ] Отключить `WdiServiceHost`, починить: тип запуска стал «Вручную»,
      а если служба не стартанула — это попало в «ЗАМЕЧАНИЯ» отчёта,
      а не в ошибки, и служба считается исправленной.
- [ ] Твикер в автозагрузке, возвращающий службу в `Disabled`: утилита
      должна показать её как не исправленную и написать, что состояние
      не изменилось, а не отчитаться об успехе.
- [ ] Отключить `bam`, починить, перезагрузиться, `sc query bam` — `RUNNING`.
- [ ] Снять все галочки — главная кнопка гаснет.
- [ ] «Выбрать все» ставит галочки только на доступных строках.

## Перезагрузка

- [ ] «Позже» — окно закрывается, компьютер не перезагружается.
- [ ] «Перезагрузить» — окно отсчёта, цифра уменьшается каждую секунду.
- [ ] «Отменить» — `shutdown /a` срабатывает, перезагрузки нет.
- [ ] Ничего не нажимать — через 10 секунд уходит в перезагрузку.
- [ ] Выполнить в отдельном окне `shutdown /r /t 600`, потом нажать
      «Перезагрузить» в утилите: должно появиться сообщение, что перезагрузка
      уже запланирована другой программой, а чужой отсчёт — продолжиться.
      Потом не забыть `shutdown /a`.

## Отчёт

- [ ] Файл `RuRBW_Report_гггг-мм-дд_чч-мм.txt` появился на рабочем столе,
      путь показан в окне.
- [ ] Открыть Блокнотом — кириллица читается.
- [ ] Колонка «Было» показывает состояние до починки, даже если отчёт сохранён
      после неё и после нескольких «Обновить».
- [ ] В шапке есть предупреждение про имя компьютера, в конце — итоги
      и подпись.
- [ ] Разделы «ОШИБКИ» и «ЗАМЕЧАНИЯ» не путаются между собой.
- [ ] Рабочий стол перенесён в OneDrive — файл кладётся туда, куда указывает
      `GetFolderPath('Desktop')`.

## Интерфейс

- [ ] Заголовок окна `RuRBW Service Restorer | rrbw.pro`, окно не тянется,
      «Развернуть» неактивна.
- [ ] Строка состояния внизу тёмная. `StatusStrip` плохо поддаётся перекраске;
      если полоса всё равно светло-серая — заменить её на обычную `Panel`
      с двумя `Label`.
- [ ] Прокрутка колесом: строки перерисовываются без мусора и мерцания.
- [ ] Выделение строки не съедает красную и жёлтую подсветку.
- [ ] Клик по любому месту доступной строки переключает галочку,
      по недоступной — ничего не делает.
- [ ] Длинное описание переносится, а не обрезается на середине слова.
- [ ] Масштаб экрана 125% и 150%: окно просто крупнее, текст не обрезан.
- [ ] Экран 1366x768: окно влезает целиком.

## Окно как в макете

- [ ] Свой тёмный заголовок: логотип 16 px, название, три кнопки справа.
      «Свернуть» подсвечивается при наведении и сворачивает окно, клик
      по значку на панели задач возвращает его. «Развернуть» серая, курсор
      «запрещено». «Закрыть» краснеет при наведении и закрывает окно.
- [ ] Окно перетаскивается за заголовок.
- [ ] В шапке логотип 36 px, под названием — значок Discord и ссылка.
      При наведении значок и текст светлеют, клик открывает Discord
      в браузере без прав администратора.
- [ ] Названия служб в таблице не обрезаются многоточием.
- [ ] Описания переносятся по словам, а не посреди слова — особенно на системе
      с включённой UTF-8 (кодовая страница 65001), где раньше было «нель|зя».
- [ ] Полоса прокрутки справа тёмная и тонкая. Колесо мыши листает по 2 строки,
      ползунок можно тянуть мышью, клик по дорожке листает на страницу.
- [ ] «Выбрать все» — стилизованный флажок, не системный. Когда чинить нечего,
      он полупрозрачный и не нажимается.
- [ ] Кнопки со скруглёнными углами, текст «Включить выбранные службы» виден
      целиком. Во время работы подпись меняется на «Включение…», кнопки
      сдвигаются под новую ширину.
- [ ] Во время включения служб в карточке крутится красная дуга.
- [ ] Диалоги («Службы включены», «Отчёт сохранён», отсчёт перезагрузки)
      открываются карточкой поверх затемнённого окна, а не отдельным окном.
      Enter нажимает главную кнопку, Esc — вторую.
- [ ] Экран «Нужны права администратора» (нажать «Нет» в UAC): замок,
      заголовок, текст по центру, красная кнопка, код ошибки. Повторный отказ
      меняет строку с кодом на красное пояснение.
- [ ] Значок программы на панели задач — логотип сервера.

## Следы в системе

- [ ] Список файлов в `%TEMP%` до запуска и после закрытия — разницы нет.
- [ ] После закрытия не появилось новых задач в планировщике
      (`schtasks /query`), служб и записей в автозагрузке.
- [ ] После нажатия «Сохранить отчёт» на диске появился ровно один новый файл.
- [ ] Defender и SmartScreen молчат при запуске по боевой ссылке.

## Разные системы

- [ ] Windows 10 21H2 и 22H2, Windows 11 23H2 и 24H2.
- [ ] Английская Windows: интерфейс остаётся русским, определение состояния
      не ломается (оно не парсит локализованный текст).
- [ ] Запуск в PowerShell 7 (`pwsh`) — кто-нибудь обязательно попробует.
- [ ] Файл скачан на диск и запущен из админского cmd через
      `powershell -NoProfile -ExecutionPolicy Bypass -Command "iex (Get-Content .\fix.ps1 -Raw -Encoding UTF8)"` —
      должен работать, `$PSScriptRoot` нигде не используется.
      Через `-File` запуск не поддерживается: без BOM Windows PowerShell 5.1
      на русской Windows прочитает файл в 1251 и не разберёт его.
